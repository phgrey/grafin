antigravity vs cursor vs firebase

When comparing **Google Antigravity**, **Cursor**, and **Firebase**, you are looking at an intersection of **agent-first AI coding environments**, **AI-first code editors**, and a **cloud backend/app development platform**. `While **Cursor** and **Antigravity** are competing AI integrated development environments (IDEs) built as forks of VS Code, **Firebase** is a managed cloud platform providing databases, authentication, and hosting that both AI tools interact with`. [](https://www.youtube.com/watch?v=rLf5jtQ-D0E&t=237)

![](%7BpageTitle%7D/QFgvdUtSxW0v0AAAAASUVORK5CYII=.png)YouTube·Nathan Covey +4

Core Differences in Philosophy

-   **Google Antigravity**: An **agent-first IDE** powered primarily by Google's Gemini models. It flips the traditional paradigm by making you a "task manager" over multi-agent loops that can autonomously run terminal commands, launch browsers, and generate verifiable audit artifacts. It natively integrates deeply with the Google Cloud and Firebase ecosystems. [](https://medium.com/data-science-in-your-pocket/cursor-vs-google-antigravity-best-ai-ide-for-vibe-coders-f3ecbd02f161)
    
    ![](%7BpageTitle%7D/wARtVQ2bT8nHAAAAABJRU5ErkJggg==.png)Medium·Mehul Gupta +3
-   **Cursor**: A polished, highly mature **AI-first code editor** built for speed and tight integration with models like Claude and GPT. It excels as an assistant for local codebases, giving you granular control over autocomplete, inline edits, and manual steering. [](https://www.youtube.com/watch?v=rLf5jtQ-D0E&t=237)
    
    ![](%7BpageTitle%7D/QFgvdUtSxW0v0AAAAASUVORK5CYII=.png)YouTube·Nathan Covey +3
-   **Firebase**: A backend-as-a-service (BaaS) and app platform by Google. Rather than an editor, it provides cloud infrastructure (Firestore, Auth, hosting, serverless functions). Google's ecosystem strategy ties Firebase tightly into modern AI tools like [Google AI Studio](https://aistudio.google.com/) and Antigravity to fast-track full-stack app creation. [](https://www.linkedin.com/posts/david-t-aerne_%F0%9D%97%9B%F0%9D%97%BC%F0%9D%98%84-%F0%9D%97%94%F0%9D%97%BB%F0%9D%98%81%F0%9D%97%B6%F0%9D%97%B4%F0%9D%97%BF%F0%9D%97%AE%F0%9D%98%83%F0%9D%97%B6%F0%9D%98%81%F0%9D%98%86-%F0%9D%97%AA%F0%9D%97%BC%F0%9D%97%BF%F0%9D%97%B8%F0%9D%98%80-activity-7398474863725801472-4yIL)
    
    ![](%7BpageTitle%7D/uoMGoGSVPDCmBQSJcBagDoCawAv4CyJz5Ou100U7AAAAAElFTkSuQmCC.png)LinkedIn·David Aerne +2

1.  **The Backend (Firebase):** Provides your database, user login, and hosting destination.

LangGraph + macPilot

Integrating **LangGraph** with **MacPilot (MacPilot CLI)** allows you to build an advanced, stateful multi-agent system that can autonomously execute complex workflows directly on your macOS operating system. 

Instead of an AI that simply suggests code, this combination results in an **AI OS-Agent** that can interact with your file system, control local applications, and handle multi-step computer tasks using natural language. 

___

Understanding the Two Components

-   **LangGraph**: LangChain’s orchestration framework designed for building **stateful, multi-agent runtimes**. It allows you to model agent workflows as cyclic graphs (loops), manage complex memory states, and introduce human-in-the-loop validation checkpoints. [](https://towardsdatascience.com/using-langgraph-and-mcp-servers-to-create-my-own-voice-assistant/)
    
    ![](%7BpageTitle%7D/A5z7yb7daSajPwffrQSAAEQAAEQAAEQAAEQAAEQAAEQAAEQAAEQAAH4WfsLHHiKr9hxmpcAAAAASUVORK5CYII=.png)Towards Data Science +1
-   **MacPilot CLI**: An open-source **Model Context Protocol (MCP) server** that exposes native macOS capabilities as structured tools for AI assistants. Running entirely on-device, it leverages native macOS frameworks to provide screen analysis, file system management, and deep application automation. [](https://mcpmarket.com/server/macpilot-cli)
    
    ![](%7BpageTitle%7D/ph6xRF+3npvXeF26QRkVRMZ8+LHUtRD3iM4bLo32fc260zddzx847X7J5xNHSSx1JOFWO4bqUf7PiJGPrBjlXxK79a15R98omNLm0LIYQQQgghhBBCCCGEEEIIIcSIHz2ZerG2mUo7AAAAAElFTkSuQmCC.png)MCP Market +2

___

The Power of the Integration

When you link MacPilot’s OS tools to LangGraph's state machine, your agents gain advanced computing capabilities: 

```scss
LangGraph Orchestrator (State Management & Decision Loops)
                          │
                          ▼ (MCP Tool Call)
             MacPilot CLI (On-Device JSON/Tools)
                          │
                          ▼ (System Frameworks)
               Native macOS Control & UI
```

1.  **Cyclic Error Recovery**: If an agent attempts to open an application or run a script via [MacPilot](https://macpilot.macupdate.com/) and hits a system permissions hurdle, LangGraph loops the failure back into the graph state. The agent can then autonomously reason through a recovery path. [](https://github.com/adeelahmad/MacPilot)
    
    ![](%7BpageTitle%7D/A1GiDZXoM3d5AAAAAElFTkSuQmCC.png)GitHub
2.  **No Image Token Cost**: Unlike traditional visual OS agents that constantly upload desktop screenshots to cloud APIs (costing significant latency and money), MacPilot natively extracts structure from macOS. LangGraph processes this lightweight structured text/JSON state. [](https://www.linkedin.com/posts/maxghenis_i-just-launched-openmessage-a-google-messages-activity-7426650670939930624-IgUr)
    
    ![](%7BpageTitle%7D/uoMGoGSVPDCmBQSJcBagDoCawAv4CyJz5Ou100U7AAAAAElFTkSuQmCC.png)LinkedIn·Max Ghenis
3.  **Complex Multi-App Chains**: You can design graphs where _Agent A_ fetches emails, _Agent B_ analyzes a spreadsheet locally, and _Agent C_ interacts with a desktop presentation app via MacPilot's deep UI automation systems. [](https://github.com/adeelahmad/MacPilot)
    
    ![](%7BpageTitle%7D/A1GiDZXoM3d5AAAAAElFTkSuQmCC.png)GitHub +1

___

Step-by-Step Integration Blueprint

1\. Prepare MacPilot CLI 

First, download the native binary from the official repositories. Ensure your terminal or Python IDE has been granted **Accessibility** and **Screen Recording** permissions in macOS _System Settings > Privacy & Security_. [](https://github.com/huhu415/macPilotCli)

![](%7BpageTitle%7D/A1GiDZXoM3d5AAAAAElFTkSuQmCC.png)GitHub

2\. Create the LangGraph MCP Client 

Because MacPilot runs natively over Anthropic's **Model Context Protocol (MCP)**, you can ingest its capabilities instantly into LangGraph using an asynchronous MCP client. [](https://www.youtube.com/watch?v=yZGjVA4uDc4)

![](%7BpageTitle%7D/QFgvdUtSxW0v0AAAAASUVORK5CYII=.png)YouTube·CampusX +1

Below is a Python template initializing a LangGraph state machine powered by MacPilot's on-device tools: [](https://www.youtube.com/watch?v=F9mgEFor0cA&vl=en&t=1661)

![](%7BpageTitle%7D/QFgvdUtSxW0v0AAAAASUVORK5CYII=.png)YouTube·Kenny Liao

python

```python
import asyncio
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

from langchain_openai import ChatOpenAI
from langgraph.prebuilt import create_react_agent
from langgraph.checkpoint.memory import MemorySaver

# 1. Point to your local MacPilot binary
server_params = StdioServerParameters(
    command="/usr/local/bin/macpilotcli",  # Adjust to your binary path
    args=[]
)

async def main():
    # 2. Establish connection to the MacPilot MCP Server
    async with stdio_client(server_params) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()

            # Fetch tools exposed by MacPilot (e.g., system_control, finder_ops)
            mcp_tools = await session.list_tools()

            # 3. Format the tools for LangGraph's consumption
            langchain_tools = [convert_mcp_to_langchain(t) for t in mcp_tools.tools]

            # 4. Initialize LLM Engine
            model = ChatOpenAI(model="gpt-4o", temperature=0)

            # 5. Define persistence memory for multi-turn OS workflows
            memory = MemorySaver()

            # 6. Build the LangGraph State Engine
            agent_executor = create_react_agent(
                model, 
                tools=langchain_tools, 
                checkpointer=memory
            )

            # Example OS-level multi-step instruction
            config = {"configurable": {"thread_id": "macos_session_1"}}
            inputs = {"messages": [("user", "Create a folder named 'Project_Alpha' in Documents, hide it using system flags, and open it in Finder.")]}

            async for event in agent_executor.astream(inputs, config):
                print(event)

if __name__ == "__main__":
    asyncio.run(main())
```

Use code with caution.

Recommended Safeguards

Giving an autonomous graph execution access to your primary operating system can carry risks. It is best practice to: 

-   **Implement LangGraph Breakpoints**: Configure standard human-in-the-loop checkpoints (`interrupt_before=["tools"]`) so the agent pauses and requests your permission before executing highly intrusive terminal commands or file overrides. [](https://www.youtube.com/watch?v=SVqnhMZ0Du8&t=3184)
    
    ![](%7BpageTitle%7D/QFgvdUtSxW0v0AAAAASUVORK5CYII=.png)YouTube·Kenny Liao
-   **Isolate Environments**: Whenever possible, run your LangGraph + MacPilot system inside a dedicated test user account or temporary virtual machine rather than your primary root desktop workspace.

is there a go / c++ based langgraph alternative?

`Yes, there are native **Go** and **C++** alternatives to LangGraph`. 

If you are trying to escape Python's Global Interpreter Lock (GIL) or need to deploy stateful, cyclic AI agents to low-latency infrastructure, robotics, or edge computing, you no longer have to build graph orchestration from scratch. [](https://www.reddit.com/r/LocalLLaMA/comments/1m0hgtt/why_langgraph_overcomplicates_ai_agents_and_my_go/)

![](%7BpageTitle%7D/w9I8fQSbfzPEQAAAABJRU5ErkJggg==.png)Reddit·r/LocalLLaMA +1

___

1\. Go Alternatives to LangGraph

Go has a rapidly maturing ecosystem for cyclic, stateful multi-agent graphs. The top frameworks that mirror LangGraph's architecture include: [](https://lango.rpcx.io/en/index.html)

![](%7BpageTitle%7D/url=https.idunno)lango.rpcx.io +1

-   **LangGraphGo**: This is the closest literal port of LangGraph's concepts to Go. It provides **compile-time type-safe state management**, cyclic graph workflows, multi-agent orchestrations, and built-in persistence layers. It even includes LangGraph-style **time travel** (checkpointing and replaying state) and native Model Context Protocol (MCP) support. [](https://lango.rpcx.io/en/index.html)
    
    ![](%7BpageTitle%7D/url=https.idunno)lango.rpcx.io
-   **LangDAG**: A lightweight, high-performance Go alternative purpose-built for production workloads. It abstracts conversation orchestration into a single Go binary with a **~1ms overhead**. Notably, it features a **built-in LangGraph importer** that lets you migrate your existing SQLite or JSON checkpoints directly into Go. 
-   **Eino (by ByteDance)**: An enterprise-grade AI orchestration framework designed completely through an idiomatic Go lens. It uses strict typing, interfaces, and a native graph builder (`NewGraph()`) to chain together loaders, retrievers, routers, and models for massive-scale routing without Python's performance penalties. [](https://www.reddit.com/r/LocalLLaMA/comments/1m0hgtt/why_langgraph_overcomplicates_ai_agents_and_my_go/)
    
    ![](%7BpageTitle%7D/w9I8fQSbfzPEQAAAABJRU5ErkJggg==.png)Reddit·r/LocalLLaMA +1
-   **go-agent (by Protocol-Lattice)**: This framework provides explicit **graph workflows** featuring deterministic control flows. You can declare function nodes, agent nodes, and use a specialized `NewJoinNode` barrier to map-reduce and synchronize fan-out parallel agent execution safely across goroutines. [](https://github.com/Protocol-Lattice/go-agent)
    
    ![](%7BpageTitle%7D/A1GiDZXoM3d5AAAAAElFTkSuQmCC.png)GitHub

___

2\. C++ Alternatives to LangGraph

In the C++ landscape, options are more specialized and generally targeted toward edge AI, games, and embedded systems: [](https://github.com/ouxianghui/langgraph-cpp)

![](%7BpageTitle%7D/A1GiDZXoM3d5AAAAAElFTkSuQmCC.png)GitHub

-   **langgraph-cpp**: An independent, community-driven C++23 AI agent framework designed to mimic LangGraph's runtime. It implements **stateful graph execution, SQLite-backed persistence, streaming events, and human-in-the-loop interrupts** natively in C++. It is optimized for running local LLM applications and robotics pipelines without requiring a Python interpreter. [](https://github.com/ouxianghui/langgraph-cpp)
    
    ![](%7BpageTitle%7D/A1GiDZXoM3d5AAAAAElFTkSuQmCC.png)GitHub
-   **Microsoft Semantic Kernel (C++ Flavour)**: While Semantic Kernel is primarily famous for C#/.NET and Python, Microsoft maintains native C++ experimental hooks for its core orchestrations. It allows you to build step-by-step native pipelines, though it leans heavily toward linear chains and hierarchical structures rather than the complex, cyclic looping found in LangGraph. [](https://www.agentframeworkhub.com/alternatives/langgraph)
    
    ![](%7BpageTitle%7D/Z.1.jpeg)Agent Framework Hub

___

Core Tradeoffs: Go/C++ vs. Python (LangGraph)

| Metric / Feature | LangGraph (Python) | Go Alternatives (LangGraphGo / Eino) | C++ Alternatives (langgraph-cpp) |
|-------------------|-------------------------------------|--------------------------------------|------------------------------------------|
| **Type Safety** | Dynamic / Pydantic | **Compile-time** strict types | **Strict compile-time** types |
| **Concurrency** | Asyncio / Threading (GIL-bound) | **Native Goroutines & Channels** | **Native multi-threading** |
| **Overhead / Memory** | High (Heavy dependencies) | **Very low** (~1ms execution overhead) | **Minimal** (Ideal for edge / robotics) |
| **Ecosystem Size** | Massive (Thousands of integrations) | Moderate (Rapidly growing via MCP) | Niche (Requires writing custom bindings) |

Alternative Infrastructure Route: Temporal

If your primary concern with LangGraph is **state persistence and fault-tolerant workflows** rather than the literal AI model primitives, you should also look into **Temporal**. “Temporal offers SDKs in Go... If your primary language is not Python, Semantic Kernel (for enterprise) or Temporal (for infrastructure-grade workflows) are your best options.”, as noted by [Best LangGraph Alternatives (2026) — 5 Options](https://thinking.inc/en/tool-comparisons/langgraph-alternatives/). Temporal allows you to write robust, distributed, stateful agent graphs using pure, idiomatic Go code. [](https://www.sim.ai/library/langgraph-alternatives)

can langgraph import/export (save/load) graph and/or it's state?

Yes. LangGraph separates this capability into two distinct concepts: **saving/loading runtime state** (dynamic history) and **exporting/importing graph configurations** (static topology). 

How both dimensions operate differs significantly. 

___

1\. Saving & Loading Runtime State (Checkpoints)

LangGraph features an automated persistence layer driven by **Checkpointers**. This is where runtime state, message history, and execution variables live. 

-   **Auto-Save & Auto-Load:** “Auto-save and auto-load are another “implicit” feature of checkpointer. You don't need to manually call save() or load() , every invoke() or stream() call automatically triggers.”, as noted by [Easton](https://eastondev.com/blog/en/posts/ai/20260424-langgraph-agent-architecture/). 
-   **Threads:** State is automatically tracked using a unique `thread_id` inside a context configuration (`RunnableConfig`). 
-   **Format:** Under the hood, LangGraph defaults to `JsonPlusSerializer`. This serializes Python data objects, Pydantic objects, and LangChain message structures cleanly into JSON or database entries. [](https://eastondev.com/blog/en/posts/ai/20260424-langgraph-agent-architecture/)
    
    ![](%7BpageTitle%7D/qVFQJRGPAAAAAASUVORK5CYII=.png)eastondev.com

Fetching and Overriding State Manually 

You can target, inspect, or modify the state of a thread at any given execution checkpoint: 

python

```python
# Setup your compiled graph with a memory saver checkpointer
from langgraph.checkpoint.memory import MemorySaver
app = graph.compile(checkpointer=MemorySaver())

config = {"configurable": {"thread_id": "session_abc_123"}}

# 1. READ / EXPORT state data
current_state = app.get_state(config)
print(current_state.values)       # Prints the actual dictionary of your state
print(current_state.next)         # Shows the next scheduled node to execute

# 2. LOAD / IMPORT / OVERRIDE state manually
# This lets you update memory or force-inject variables mid-run
app.update_state(config, {"internal_memory": "User prefers concise answers"})
```

Use code with caution.

If you deploy this to production, you can replace the in-memory `MemorySaver` with persistent databases using official packages like `SqliteSaver`, `PostgresSaver`, or `AerospikeStore`. [](https://aerospike.com/blog/aerospike-langgraph/)

![](%7BpageTitle%7D/gfyB+elO2YRAPTtAAAAAElFTkSuQmCC.png)Aerospike

2\. Exporting & Importing Graph Structure (The Code/DAG)

Exporting the **code definition** or Directed Acyclic Graph (DAG) layout differs because a LangGraph relies on native execution paths—meaning its nodes are standard Python or TypeScript functions. [](https://docs.langchain.com/oss/python/langgraph/use-graph-api)

![](%7BpageTitle%7D/QAAAABJRU5ErkJggg==.png)Docs by LangChain +1

Via LangGraph Studio & Cloud CLI 

If you use LangGraph Cloud or [LangGraph Studio](https://docs.langchain.com/langsmith/application-structure), you can cleanly package and bundle your workflows: [](https://www.linkedin.com/posts/atiqmansoori7_day-15-activity-7386612281201135616-23TX)

-   This approach reads a standardized configuration file called `langgraph.json`. The json maps out where your compiled graph variable sits inside your codebase package (`./your_package/your_file.py:graph`).     ![](%7BpageTitle%7D/QAAAABJRU5ErkJggg==.png)Docs by LangChain +4

Via Structural Serialization (JSON/Mermaid) 

Because your nodes contain raw Python execution logic, **you cannot cleanly turn a complex, compiled Python graph code block into a pure, executable structural JSON file** natively via a library function and load it back into memory later.

python

```python
# Export the Graph Architecture to standard Mermaid markdown string
mermaid_string = app.get_graph().draw_mermaid()

png_bytes = app.get_graph().draw_mermaid_png()
with open("graph_schema.png", "wb") as f:
    f.write(png_bytes)
```

1\. Storing State Locally (Checkpoints)

You are on the right track. `JsonPlusSerializer` is LangGraph's internal serialization tool. To store checkpoints locally in a structured text document (like a local JSON file or a lightweight SQLite database), you have two choices: [](https://reference.langchain.com/python/langgraph.checkpoint/serde/jsonplus/JsonPlusSerializer)

![](%7BpageTitle%7D/9F+Uv4hA+XTQAODEAAAAASUVORK5CYII=.png)LangChain

-   **The Easiest Way (SQLite):** Use the official, built-in `SqliteSaver`. It manages a single, structured file locally and uses `JsonPlusSerializer` under the hood automatically. [](https://docs.langchain.com/langsmith/cli)
    
    ![](%7BpageTitle%7D/QAAAABJRU5ErkJggg==.png)Docs by LangChain
-   **The Raw Document Way (Custom JSON File Saver):** If you specifically need a plaintext `.json` document, you must inherit from `BaseCheckpointSaver` and implement your own local writing methods. 

Here is the exact code to build a **local JSON file checkpointer**: 

python

```python
import json
import os
from typing import Any, Optional
from langgraph.checkpoint.base import BaseCheckpointSaver, Checkpoint, CheckpointMetadata, CheckpointTuple
from langgraph.checkpoint.serde.jsonplus import JsonPlusSerializer
from langchain_core.runnables import RunnableConfig

class LocalJsonFileSaver(BaseCheckpointSaver):
    def __init__(self, file_path: str = "graph_state.json"):
        # Explicitly pass the standard LangGraph serializer
        super().__init__(serde=JsonPlusSerializer())
        self.file_path = file_path
        # Initialize an empty storage file if it does not exist
        if not os.path.exists(self.file_path):
            with open(self.file_path, "w") as f:
                json.dump({}, f)

    def _read_db(self) -> dict:
        with open(self.file_path, "r") as f:
            return json.load(f)

    def _write_db(self, data: dict):
        with open(self.file_path, "w") as f:
            json.dump(data, f, indent=2)

    def get_tuple(self, config: RunnableConfig) -> Optional[CheckpointTuple]:
        """Retrieves a checkpoint by thread_id and checkpoint_id."""
        db = self._read_db()
        thread_id = config["configurable"]["thread_id"]
        checkpoint_id = config["configurable"].get("checkpoint_id")

        if thread_id not in db:
            return None

        # If no checkpoint_id specified, grab the latest one
        if not checkpoint_id:
            checkpoint_id = max(db[thread_id].keys())

        raw_data = db[thread_id][checkpoint_id]

        # Deserialize using LangGraph's internal system
        checkpoint = self.serde.loads(raw_data["checkpoint"].encode('utf-8'))
        metadata = json.loads(raw_data["metadata"])

        return CheckpointTuple(
            config=config,
            checkpoint=checkpoint,
            metadata=metadata,
            parent_config=raw_data.get("parent_config")
        )

    def put(self, config: RunnableConfig, checkpoint: Checkpoint, metadata: CheckpointMetadata, new_versions: Any) -> RunnableConfig:
        """Saves the current state into the JSON document."""
        db = self._read_db()
        thread_id = config["configurable"]["thread_id"]
        checkpoint_id = checkpoint["id"]

        if thread_id not in db:
            db[thread_id] = {}

        # Serialize into JSON strings safely
        db[thread_id][checkpoint_id] = {
            "checkpoint": self.serde.dumps(checkpoint).decode('utf-8'),
            "metadata": json.dumps(metadata),
            "parent_config": config.get("parent_config")
        }

        self._write_db(db)
        return config
```

Use code with caution.

2\. Node Saving: Textual Code vs. Code References

For node saving, **you should save references to the code** (module paths and strings) rather than attempting to serialize the actual Python/JS runtime function bytecode. 

Why you can't save raw function code: 

A node in LangGraph is a live execution routine containing standard code statements, closures, third-party libraries, and file system handles. Standard string serializers (like JSON) cannot capture a runtime function. While tools like `pickle` or `marshal` can convert small Python functions to byte arrays, they are fragile, highly insecure, break instantly if python versions change, and cannot transfer across languages (e.g., Python to JavaScript). [](https://reference.langchain.com/python/langgraph.checkpoint/serde/jsonplus/JsonPlusSerializer)

![](%7BpageTitle%7D/9F+Uv4hA+XTQAODEAAAAASUVORK5CYII=.png)LangChain +2

How LangGraph CLI / Studio handles this: 

LangGraph Studio and the CLI **never** extract or serialize function text into database files. They use a **declarative manifest mapping model**. [](https://www.youtube.com/watch?v=T9qYg_WFfQo&t=536)

![](%7BpageTitle%7D/QFgvdUtSxW0v0AAAAASUVORK5CYII=.png)YouTube·LangChain +1

The layout file is always named **`langgraph.json`**. It points to string identifiers mapping out exactly where your actual codebase files reside: [](https://reference.langchain.com/python/langgraph-cli)

![](%7BpageTitle%7D/9F+Uv4hA+XTQAODEAAAAASUVORK5CYII=.png)LangChain +1

json

```json
{
  "dependencies": ["."],
  "graphs": {
    "my_agent_graph": "./src/agent/workflow.py:graph"
  },
  "env": ".env"
}
```

Use code with caution.

When you start LangGraph Studio or run `langgraph dev` in the CLI, it executes a local server. The server loads your infrastructure natively using the paths specified in `langgraph.json`. [](https://reference.langchain.com/python/langgraph-cli)

![](%7BpageTitle%7D/9F+Uv4hA+XTQAODEAAAAASUVORK5CYII=.png)LangChain +3

-   The **graph layout** (nodes, conditional edges, routing maps) is read directly out of the live compiled object in memory via `.get_graph()`.
-   When a state checkpoint is loaded from the database, it restores only the _variables_ (the message array, token tallies, boolean switches).
-   The system feeds those variables directly into the standard Python/JS nodes that are already executing natively on your machine. [](https://reference.langchain.com/python/langgraph.store)
    
    ![](%7BpageTitle%7D/9F+Uv4hA+XTQAODEAAAAASUVORK5CYII=.png)LangChain +2

It can rewrite the `"edges"` mapping inside your shared JSON manifest immediately. When the conversation returns to Semantic Kernel, the graph follows the newly modified edge. 

___

3\. Step-by-Step State & Graph Handshake

To implement this bi-directional flow efficiently without encountering race conditions, map your storage layer into three distinct buckets: 

```scss
┌────────────────────────────────────────────────────────────────────────┐
│                              LOCAL STORAGE                             │
├───────────────────┬──────────────────────────────┬─────────────────────┤
│ 1. Graph Manifest │ 2. Live Node Registry        │ 3. Checkpoint Store │
│ (The JSON Layout) │ (The actual code files/APIs) │ (Variable States)   │
└───────────────────┴──────────────────────────────┴─────────────────────┘
```

1.  **Graph Manifest (`graph.json`)**: Tracks **where** things go. Both sides can read and write to this file to dynamically alter nodes and conditions.
2.  **Live Node Registry**: Tracks **what** happens at each step. This acts as a library of string keys mapping to functional execution logic. Semantic Kernel maps strings to native C# / Python core functions, while Teams AI maps strings to JavaScript / TypeScript endpoint automation scripts.
3.  **Checkpoint Store (`state.json`)**: Tracks **the current values** of a live conversation thread. It records data fields like `{"current_node": "intent_classifier", "history": [...]}`. [](https://blogg.sikt.no/building-an-ai-microsoft-teams-bot-with-langgraph-and-azure-openai-bb8bf2270c1d)
    
    ![](%7BpageTitle%7D/wARtVQ2bT8nHAAAAABJRU5ErkJggg==.png)Sikt – Kunnskapssektorens tjenesteleverandør +3

Implementation Advice: Avoid the Code Serialization Trap

Do not attempt to pass raw, executable function expressions or script code inside the JSON string from Teams AI to Semantic Kernel. Keep your manifest pure and declarative: **only pass structural layouts, configuration variables, and data payloads.** Let each framework map those text strings to its own native code compilation blocks locally. [](https://www.youtube.com/watch?v=iVCH1PONcZY&t=8)

```python
import json
import logging
from typing import Dict, Any, List
from semantic_kernel import Kernel
from semantic_kernel.functions import kernel_function
from semantic_kernel.functions.kernel_arguments import KernelArguments

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger("TeamsSKGraph")

# =====================================================================
# 1. CORE CODEBASE: SHARED CUSTOM NODE FUNCTIONS (Reusable Core)
# =====================================================================
class CustomNodeRepository:
    """
    Your central, framework-agnostic business logic repository.
    Decorators allow Semantic Kernel to digest them natively.
    """

    @kernel_function(name="CategorizeInput", description="Analyzes intent and routes the query")
    def categorize_input(self, user_query: str) -> str:
        logger.info(f"Executing Node: CategorizeInput with data: '{user_query}'")
        query_lower = user_query.lower()
        if "billing" in query_lower or "refund" in query_lower:
            return "billing"
        if "critical" in query_lower or "break" in query_lower:
            return "critical"
        return "general"

    @kernel_function(name="ProcessBilling", description="Simulates payment or ledger adjustments")
    def process_billing(self, user_query: str) -> str:
        logger.info("Executing Node: ProcessBilling")
        return "Billing workflow processed successfully."


# =====================================================================
# 2. RUNTIME LOGIC: DYNAMIC JSON MANIFEST DESERIALIZATION ENGINE
# =====================================================================
class DynamicGraphEngine:
    def __init__(self, kernel: Kernel, manifest_json: str):
        self.kernel = kernel
        self.manifest = json.loads(manifest_json)
        self.nodes = {node["id"]: node for node in self.manifest["nodes"]}
        self.edges = self.manifest["edges"]

    def _generate_adaptive_card(self, node_id: str, state: Dict[str, Any]) -> Dict[str, Any]:
        """Creates a schema payload that Teams AI reads to render custom elements."""
        return {
            "type": "AdaptiveCard",
            "version": "1.4",
            "body": [
                {"type": "TextBlock", "text": f"⚠️ Human Intervention Required at Node: {node_id}", "weight": "Bolder", "size": "Medium"},
                {"type": "TextBlock", "text": f"Current State Snapshot: {json.dumps(state)}", "wrap": True},
                {"type": "Input.Text", "id": "human_override_input", "placeholder": "Enter instructions or clearance token..."}
            ],
            "actions": [
                {"type": "Action.Submit", "title": "Approve & Resume Flow", "data": {"action": "approve", "node_halted": node_id}}
            ]
        }

    async def execute_workflow(self, state: Dict[str, Any], start_node_id: str) -> Dict[str, Any]:
        """
        Executes the graph dynamically by traversing nodes and edges found in the JSON data.
        Changes made to the manifest JSON mid-flight are parsed dynamically.
        """
        current_node_id = start_node_id

        while current_node_id:
            logger.info(f"Transitioning to Graph Step: [{current_node_id}]")
            node = self.nodes.get(current_node_id)

            if not node:
                logger.error(f"Error: Node path '{current_node_id}' does not exist in manifest.")
                break

            # --- HANDLE HUMAN-IN-THE-LOOP (HITL) PAUSE ---
            if node["type"] == "human_in_the_loop":
                logger.warning(f"Halt triggered at '{current_node_id}'. Yielding Adaptive Card block to Teams AI context.")
                card_schema = self._generate_adaptive_card(current_node_id, state)

                # Update our session store state to flag this process as pending action
                state["status"] = "PAUSED_FOR_HITL"
                state["next_node_override"] = current_node_id
                state["adaptive_card_payload"] = card_schema
                return state # Return processing back to Teams AI framework boundary

            # --- HANDLE STANDARD SEMANTIC KERNEL EXECUTION ---
            if node["type"] == "llm_agent" or node["type"] == "native_code":
                plugin_name = node["plugin_name"]
                function_name = node["native_function"]

                # Fetch target runtime component from Semantic Kernel memory space
                sk_function = self.kernel.get_function(plugin_name, function_name)

                # Map variables into Semantic Kernel arguments context
                args = KernelArguments()
                for key, val in state.items():
                    args[key] = val

                # Execute native step inside the engine loop
                result = await self.kernel.invoke(sk_function, args)

                # Push execution value back into running state document context
                state["last_node_output"] = str(result)
                if current_node_id == "intent_classifier":
                    state["ticket_status"] = str(result)

            # --- DYNAMIC EDGE EVALUATION AND ROUTING PATHWAY ---
            next_node_id = None
            for edge in self.edges:
                if edge["from"] == current_node_id:
                    condition = edge.get("condition")
                    if condition:
                        # Safely eval python conditions out of manifest string (e.g. ticket_status == 'billing')
                        # In production environments, parse this syntax string securely via custom tokenizer
                        try:
                            eval_env = {"state": state}
                            if eval(condition, {}, eval_env):
                                next_node_id = edge["to"]
                                break
                        except Exception as e:
                            logger.error(f"Condition mapping error on edge: {condition}. Exception: {e}")
                    else:
                        next_node_id = edge["to"]
                        break

            current_node_id = next_node_id

        state["status"] = "COMPLETED"
        return state


# =====================================================================
# 3. RUNTIME EXECUTION BOOTSTRAPPER (The Orchestration Loop)
# =====================================================================
async def main():
    # 1. Initialize Semantic Kernel
    kernel = Kernel()

    # 2. Register our Framework-Agnostic Python Plugins
    node_plugin = CustomNodeRepository()
    kernel.add_plugin(node_plugin, plugin_name="ClassificationPlugin")

    # 3. A JSON Graph Manifest received from your file-system or Teams app dashboard
    shared_graph_manifest = """
    {
      "graph_id": "teams_support_matrix",
      "version": 1.0,
      "nodes": [
        {
          "id": "intent_classifier",
          "type": "llm_agent",
          "plugin_name": "ClassificationPlugin",
          "native_function": "CategorizeInput"
        },
        {
          "id": "billing_processor",
          "type": "native_code",
          "plugin_name": "ClassificationPlugin",
          "native_function": "ProcessBilling"
        },
        {
          "id": "escalation_node",
          "type": "human_in_the_loop",
          "plugin_name": "TeamsNotificationPlugin",
          "native_function": "PauseAndAlertManager"
        }
      ],
      "edges": [
        { "from": "intent_classifier", "to": "billing_processor", "condition": "state['ticket_status'] == 'billing'" },
        { "from": "intent_classifier", "to": "escalation_node", "condition": "state['ticket_status'] == 'critical'" }
      ]
    }
    """

    # Init graph interpreter
    engine = DynamicGraphEngine(kernel, shared_graph_manifest)

    # Scenario A: Simulation of a Critical Query causing a HITL Pause
    conversation_state_A = {"user_query": "This is critical! Our server room is leaking water.", "ticket_status": ""}
    output_state_A = await engine.execute_workflow(conversation_state_A, start_node_id="intent_classifier")

    print("\n--- RUN EXECUTION OUTPUT BLOCK (CRITICAL WORKFLOW) ---")
    print(json.dumps(output_state_A, indent=2))
    # This outputs a PAUSED_FOR_HITL flag along with an Adaptive Card JSON payload.
    # Pass this payload straight to your Teams AI framework turn execution code layer!

if __name__ == "__main__":
    import asyncio
    asyncio.run(main())
```

                  │ Teams AI Action Handler             │
                  │ (Catches submit payload, rewrites)  │
